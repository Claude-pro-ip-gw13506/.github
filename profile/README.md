<p>给内部系统批量开号，最怕的不是开得慢，而是开完之后两边风险串在一起：一个号触发了验证，另一批跟着受影响。这件事光靠讨论说不清，适合做一次小规模对照实验——同样的脚本、同样的运营节奏，只把出口配置换掉，看两组账号的表现有没有差别。这篇写实验怎么设计、记录哪些字段、结果怎么读。老号走一条出口、新号另开一条，是本实验的基础变量。</p>

<h2>一、先定实验假设：串号到底串在哪</h2>

<p>做对照实验之前，得先把模糊的担心写成可检验的假设。常见的假设有三条：一是同一出口上挂多个账号会互相牵连；二是新号在脏出口上更容易被要求验证；三是环境指纹共用比出口共用的影响更大。三条假设对应的实验设计不同，不能混着测。</p>

<h3>把假设写成可观测的形式</h3>
<p>不要写「会不会被关联」，写成「同一出口上挂三个以上账号时，该出口下任一账号出现验证后，24 小时内其他账号出现验证的比例」。这样才有分母、有分子、有时间窗，实验结束能算出数字，而不是停留在感觉层面。</p>

<h3>先排除干扰变量</h3>
<p>脚本行为、访问频率、访问时段、账号年龄段，这些都会影响结果。做对照时尽量让两组在这些维度上接近，只在出口配置上有差别。如果两组同时改了脚本和出口，结果没法归因。</p>

<h2>二、分组与变量：两组账号、两种出口</h2>

<p>最省事的做法是两组、每组三到五个账号。A 组是老号（注册满三个月），B 组是新号（注册一周内）。两组内部再各分两半：一半走独立出口，一半走共用出口。这样一次实验能同时看出年龄与出口两个维度的差别。</p>

<h3>A 组：老号走独立出口</h3>
<p>老号的特点是历史登录记录稳定，对出口变化的容忍度相对高一些，但也更容易因为「忽然换城市」而被注意。给老号配一条固定的原生家宽出口，城市与注册地一致，实验期内不改动。</p>

<h3>B 组：新号另开出口</h3>
<p>新号的容错空间小，头两周的登录环境最好一次到位。给新号单独开出口，不与老号共用，也不与新号之间共用。这一组要重点观察的是「首次登录与三天内的第二次登录是否出现额外验证」。</p>

<h3>对照组：共用出口</h3>
<p>为了有比较基准，需要留一小批账号走共用出口。这批账号只做最轻的操作，比如每天登录一次查看状态，避免它们的异常行为反过来影响实验结论。</p>

<h2>三、观察窗口与记录字段</h2>

<p>实验的可信度取决于记录的细度。最少要记五个字段：时间戳、账号编号、出口地址、操作类型、结果状态。结果状态分三类就够：正常、出现额外验证、请求失败。字段少但每天记，比字段多但记三天就断更有价值。</p>

<h3>每天固定两个观察时点</h3>
<p>建议选当地上午十点和晚上九点各一次，前者代表低峰，后者代表高峰。同一时点、同一操作、同一页面，减少变量。记录不要凭回忆补，当天记当天。</p>

<h3>环境侧也要记</h3>
<p>出口之外，环境是否独立同样要记。每个账号的浏览器实例名、用户目录、时区、语言各是什么，写在同一张表里。否则一旦结果有差异，你没法判断是出口的功劳还是环境的功劳。</p>

<h2>四、第一轮结果怎么读</h2>

<p>两周之后把数据摊开，先看总量再看分布。如果 A1 与 A2 的验证次数差异不明显，说明对老号而言出口独享的边际收益有限；如果 B1 与 B2 差异明显，说明新号阶段对出口更敏感。这类结论比任何经验之谈都可靠，因为它是你自己环境里跑出来的。</p>

<h3>注意样本量与偶然性</h3>
<p>每组三个账号只能给出方向性判断，不能当成定论。出现一两次差异，先看是不是集中在某一天、某个时段，如果是，很可能是线路波动而不是配置差异。至少跑满两周，再考虑是否扩大样本。</p>

<h3>区分「验证」与「失败」</h3>
<p>这两类结果的成因不同。额外验证多半与信誉、环境、行为有关；请求失败多半与出口可用性、带宽、路由有关。混在一起统计，会得出错误结论。分开算，才能对应到不同的处置动作。</p>

<h2>五、结论与放量条件</h2>

<p>实验的目的不是得出一个永远正确的结论，而是给出「现在可以放量到什么程度」的判断。放量条件建议写成三条：连续七天无额外验证；高峰时段成功率不低于九成五；备用线路切换演练成功一次。三条同时满足，再把账号量翻一倍。</p>

<h3>翻倍之后要重新观察</h3>
<p>账号从十个涨到二十个，出口数量也要跟着涨。很多时候问题不是出在单条线上，而是出在「新增的这批用了同一段资源」。翻倍后的第一周按同样方式记录，发现异常立刻回到上一次的规模。</p>

<h3>把实验沉淀成流程</h3>
<p>跑完一次实验，把分组方式、记录表、判定标准整理成模板。下次扩区、换服务方、上新脚本，直接复用这套模板，不用每次重新想。内部系统批量开号的团队，最值钱的资产就是这套可复用的验证流程。</p>

<h2>常见问答</h2>

<h3>实验要跑多久才有效？</h3>
<p>答：建议至少两周，覆盖一个完整的工作周与一个周末。只跑三四天容易把线路波动的偶然结果当成结论。样本量小的时候，两周只够给方向性判断，不足以定论。</p>

<h3>每组放几个账号合适？</h3>
<p>答：每组三到五个起步，总量控制在二十个以内。数量太少看不出差异，太多则变量难以控制。先小规模跑通记录流程，再考虑扩大。</p>

<h3>老号和新号一定要分开出口吗？</h3>
<p>答：建议分开。老号的登录历史稳定，新号处于建立期，两者的容错空间不同。混在同一条出口上，一旦新号出问题，老号也可能被牵连，而这种牵连在数据上很难追溯。</p>

<h3>结论能直接套用到别的平台吗？</h3>
<p>答：不能。不同平台的判定逻辑、风控强度、地区敏感度都不一样。这套实验方法可以复用，但具体的阈值与结论必须在你自己的目标平台上重跑一遍。</p>
